# 규정 작업실 · 세션 2 「규정 제·개정 에이전트」

세션 2 과제③을 위한 **별도의 신규 웹 프로젝트**입니다. `policy-domino`, `policy-domino-next` 저장소와 코드·수집데이터·배포를 공유하지 않습니다.

## 기능

- **업무 진입:** 자유 요청, 규정 제정·개정·근거 조사·신구 대비·검토·문서 작성 중 선택하여 시작
- **통합 작업:** 공식 현행 판본과 작성 초안 분리, 판본 복구, 담당자 결정 장부, 근거 카드, 이유서 및 시행일을 하나의 작업에 보관
- **편집·비교:** 원문 보존, 조문 단위 수정·삭제·신설, 신구조문 대조, 변경 어구 밑줄, 조문번호 이동 후보(확정 전 자동 수정 금지)
- **오류 점검:** 내부 인용, 항 번호 이동 후보, 조문 구조, 이유서 수치 불일치 탐지
- **문서:** 실제 OOXML Word(.docx) 출력, 텍스트/HTML/작업 JSON 내보내기 및 복원, 부칙·이유서·절차 체크리스트
- **AI 제안:** GitHub Pages의 Puter 계정 사용 모드(GPT·Gemini·Claude 등) 또는 보안 Node 서버(OpenAI 호환·Gemini·Anthropic) 선택. 외부 전송동의와 담당자 승인 필수

가상 예제는 **데모 자료이며 법적 근거의 유효성을 입증하는 사례가 아닙니다.**

## 공식 법령·행정규칙·자치법규 조회

‘근거·자료 → 공식 조회’에서 법령, 행정규칙, 자치법규 중 하나를 선택하고 [국가법령정보 공동활용](https://open.law.go.kr/)에서 사용하는 **공개 OC 식별값 `dori`를 기본 적용해** 검색합니다. OC 입력은 필요하지 않습니다. GitHub Pages에서 Puter 네트워크 중계를 사용하므로 로그인 및 외부 데이터 전송에 동의해야 합니다. OC 기본값 `dori`는 공개 GitHub 소스에 포함되므로 비밀키로 취급하지 않습니다. 작업 백업·localStorage에는 별도로 저장하지 않습니다.

조회 목록에서 원문 수신을 선택하면 원문, 식별번호, 공포·시행일, 취득일시와 SHA-256을 묶어 근거 카드로 등록하거나 현행 기준본으로 지정할 수 있습니다. 검색 성공과 법적 위임·효력 검증은 별개입니다. 과거·시행예정 법령은 `eflaw` 공식 API, 행정규칙·자치법규는 연혁 검색 옵션을 사용합니다. 별표의 외부 첨부 파일은 자동 원문에 포함되지 않을 수 있으므로 공식 화면에서 별도로 확인해야 합니다. 사용자가 직접 등록한 문서는 자동으로 '공식 API 확인' 상태가 되지 않습니다.

**주의:** 조회에는 기본 OC `dori`를 자동 사용합니다. 서버 측 공동활용 권한·제공 API 응답이 유효하지 않으면 실패 이유를 표시하며, 샘플 데이터로 대체하지 않습니다.

## 실행

Node.js 20 이상:

```bash
npm test
npm run check
npm start
# http://127.0.0.1:3000
```

`npm run build`는 `dist/`에 정적 사이트만 만듭니다.

### GitHub Pages

GitHub의 **Settings → Pages → Build and deployment → GitHub Actions**를 선택합니다. `main`에 push되면 `.github/workflows/ci-pages.yml`이 테스트하고 `dist/`를 배포합니다.

**GitHub Pages에서도 AI 제안을 요청할 수 있습니다.** 작업 개요의 **AI 연결 방식 → Puter 계정으로 사용**을 선택하면 브라우저에서 SDK를 필요할 때만 불러옵니다. Puter 계정 로그인이 필요하며 사용자 계정의 사용량에 따라 비용이 발생할 수 있습니다. GPT·Gemini·Claude 등 사용 가능한 모델 ID를 지정할 수 있고, 모델 접근 권한·요금은 Puter 정책에 따릅니다. 내 규정 원문은 요청 버튼과 외부 전송 동의를 누른 경우에만 전송되며, 결과는 승인 전까지 초안에 덮어쓰지 않습니다. 데이터는 제3자 서비스로 전송되므로 내부·비공개 문서는 기관 보안 정책 확인 없이 입력하면 안 됩니다.

**자체 서버 연결 모드**도 제공됩니다. 사용자가 운영하는 HTTPS API 서버 주소와 접근 토큰을 입력해야 하며 정적 Pages 자체에는 비밀키를 저장하지 않습니다. 이 저장소를 배포하기만 해서는 자체 서버가 자동 구축되는 것은 아닙니다.

### AI 서버

환경변수 `LLM_PROVIDER` (`compatible` / `gemini` / `anthropic`), `LLM_MODEL`, `LLM_API_KEY`, 필요 시 `LLM_API_URL`을 **개인 서버**에만 넣고 `npm start`를 실행하세요. `.env.example` 참고.

외부 공개 서버에 배포할 경우 필수로 `HOST=0.0.0.0`, `AI_ACCESS_TOKEN=충분히 긴 임의 토큰`, `AI_ALLOWED_ORIGINS=https://dodam-heo.github.io`를 서버의 비밀 환경변수에 설정합니다. 모델 키(`LLM_API_KEY`)와 접근 토큰은 **서버 측 비밀 환경변수**로만 관리하세요. 브라우저, GitHub Pages, Actions의 소스 코드/로그에 넣지 마세요. API 서버는 HTTPS(보안 리버스 프록시 포함)로 연결하고, 누구나 사용할 수 있는 공개 비용부담 API로 열어두지 마세요.

AI 생성 결과는 제·개정 **검토용 제안**일 뿐이며, 원문·근거·인용·절차를 자동 검증했다고 표시하지 않습니다. 별도 서버가 없어도 Puter 모드 또는 수동 기능을 선택할 수 있습니다.

## 현재 한계

공식 API 조회는 OC 인증값과 Puter 로그인 시 실행할 수 있지만, 외부 API 오류·권한 제한은 사용자에게 표시됩니다. 상위법 위임의 **법적 유효성 확인**, 법제 표준 개정지시문 형식에 대한 완전한 검사, 조문 분할·병합의 의미적 자동 확정, HWPX 파일 생성·공식 한컴 호환검증, 기관별 전자결재·발령과 기관계정별 권한관리 등은 구현·검증 범위 밖입니다. DOCX 생성은 지원하지만 모든 한글 전용 서식과 1:1 동일하지 않습니다. 자동 점검은 법률 적합성 검토가 아닙니다.

사용자 자료는 현재 브라우저의 `localStorage`에 보관하며, 개인정보·비공개 규정을 공개 서버에서 다루지 않도록 주의해야 합니다. '작업 백업' 기능으로 JSON을 별도 보관할 수 있습니다.

## 테스트와 출품 검증

- `npm run check`: 파서·비교·인용/이유서 검사·문서 연동·DOCX OOXML·법령 DRF 검색/인증/판본·AI 보안·번호이동 후보 회귀 테스트
- PR CI는 테스트 및 Pages용 정적 산출물에 필수 모듈이 모두 있는지 확인합니다. **GitHub Pages 실배포는 main 브랜치만** 허용합니다.
- 외부 API를 쓰는 기능은 OC 인증·Puter 로그인·네트워크 접근 등의 실제 사용자 환경 테스트가 따로 필요합니다. 통과한 단위 테스트만으로 실시간 공식 조회나 법적 검토가 완료되었다고 주장하지 않습니다.
